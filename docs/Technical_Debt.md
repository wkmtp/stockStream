## 🟠 高优先级债务 (P1 — V4.1 目标)

### TD-001: Orchestrator 上帝对象

| 属性 | 值 |
|------|-----|
| **文件** | `stockstream/core/orchestrator.py` |
| **严重度** | 🟠 高 |
| **SOLID 违反** | SRP (单一职责) |
| **当前问题** | 188 行单文件管理 15+ 模块生命周期、依赖注入、配置加载 |
| **影响** | 新增模块需修改 Orchestrator；单元测试困难；职责边界模糊 |
| **建议方案** | 拆分为 `LifecycleManager`(启动/停止) + `DependencyContainer`(DI) + `PipelineScheduler`(调度) |
| **预计人天** | 3 天 |
| **风险** | 中 — 影响所有模块初始化路径 |

### TD-002: Avatar 引擎缺少抽象接口

| 属性 | 值 |
|------|-----|
| **文件** | `stockstream/avatar/pipeline.py`, `stockstream/avatar/service.py` |
| **严重度** | 🟠 高 |
| **SOLID 违反** | OCP (开闭原则), DIP (依赖倒置) |
| **当前问题** | Avatar pipeline 直接依赖 Wav2Lip ONNX 具体实现，无抽象引擎接口 |
| **影响** | 新增数字人模型 (MuseTalk, SadTalker, Audio2Face) 需修改 Pipeline 核心代码 |
| **建议方案** | 定义 `AvatarEngine` ABC → `Wav2LipEngine`, 支持通过注册表配置切换 |
| **预计人天** | 2 天 |

### TD-003: 量化策略硬编码

| 属性 | 值 |
|------|-----|
| **文件** | `stockstream/agent/trader/engine.py` |
| **严重度** | 🟠 高 |
| **SOLID 违反** | OCP, DIP |
| **当前问题** | 交易规则(止损/止盈/加仓/清仓)散落在 engine.py 的条件判断中 |
| **影响** | 新增策略 (网格交易、马丁格尔、MACD 策略) 需大量修改 |
| **建议方案** | 提取 `TradingStrategy` ABC → 注册表模式，支持插件式策略 |
| **预计人天** | 2 天 |

### TD-004: 缺少统一插件注册中心

| 属性 | 值 |
|------|-----|
| **严重度** | 🟠 高 |
| **影响范围** | 全部扩展点 (AI 模型、数字人、量化策略、直播平台) |
| **当前问题** | 各模块各自维护注册逻辑，无统一入口，无法在运行时查看已注册插件 |
| **建议方案** | 在 `src/core/plugin_registry.py` 实现统一 `PluginRegistry`，支持发现/注册/热重载 |
| **预计人天** | 2 天 |

## 🟡 中优先级债务 (P2 — V4.2 目标)

### TD-005: 39 个 Agent 缺少统一基类

| 属性 | 值 |
|------|-----|
| **文件** | `stockstream/{agent_name}/engine.py` (39 个模块) |
| **严重度** | 🟡 中 |
| **当前问题** | 所有 agent 均为独立 `engine.py`，无共同接口定义 |
| **影响** | Agent 行为不一致 (start/stop/status 接口各异)，扩展新 agent 无 blueprint |
| **建议方案** | 定义 `BaseAgent` ABC 含 `init/start/stop/health/process`，所有 agent 继承 |
| **预计人天** | 2 天 |

### TD-006: trader/selector 缺少 Repository 抽象

| 属性 | 值 |
|------|-----|
| **文件** | `stockstream/agent/trader/`, `stockstream/selector/` |
| **严重度** | 🟡 中 |
| **DDD 违反** | 领域逻辑与持久化耦合 (直接 SQL 语句散落) |
| **当前问题** | 直接使用 SQLite/JSON 文件操作，切换存储需改业务逻辑 |
| **建议方案** | 引入 Repository Pattern (`TradeRepository`, `SignalRepository`) |
| **预计人天** | 2 天 |

### TD-007: 日志上下文传播不一致

| 属性 | 值 |
|------|-----|
| **文件** | 全局 |
| **严重度** | 🟡 中 |
| **当前问题** | 部分模块通过 logger=logging.getLogger(__name__)，部分通过 LogCenter，无统一 trace_id 传播 |
| **影响** | 请求链路追踪困难，生产环境排障耗时 |
| **建议方案** | 统一使用 `structlog` + contextvars trace_id，LogCenter 作为唯一入口 |
| **预计人天** | 1 天 |

### TD-008: 配置校验不完整

| 属性 | 值 |
|------|-----|
| **文件** | `src/core/config_center.py` |
| **严重度** | 🟡 中 |
| **当前问题** | `validate_required` 仅检查键存在，不验证值类型/范围 |
| **影响** | 无效配置可能导致运行时异常而非启动时拒绝 |
| **建议方案** | 集成 Pydantic v2 模型校验，启动时验证所有配置段 |
| **预计人天** | 1 天 |

### TD-009: WebSocket 无背压控制

| 属性 | 值 |
|------|-----|
| **文件** | `stockstream/web/api.py` |
| **严重度** | 🟡 中 |
| **当前问题** | WebSocket 发送使用无界队列，慢客户端可能导致 OOM |
| **建议方案** | 实现带背压的环形缓冲 (maxsize=1024)，超时丢弃旧消息 |
| **预计人天** | 1 天 |

## 🟢 低优先级债务 (P3 — V5.0 规划)

### TD-010: Matplotlib 不是线程安全的

| 属性 | 值 |
|------|-----|
| **影响** | 并发图表渲染时偶尔崩溃或产生错误图像 |
| **当前缓解** | 通过 threading.Lock 串行化调用 |
| **建议方案** | 迁移至 plotly (线程安全) 或 keepass (Rust 渲染) |
| **预计人天** | 2 天 |

### TD-011: 部分测试为占位符

| 属性 | 值 |
|------|-----|
| **文件** | `tests/tts/`, `tests/avatar/`, `tests/gpu/` |
| **当前问题** | 测试框架已就绪但具体用例覆盖不充分 |
| **建议方案** | 补充覆盖率至 85%+，添加 GPU 回归测试 |
| **预计人天** | 1 天 |

### TD-012: 硬编码的指标收集

| 属性 | 值 |
|------|-----|
| **文件** | `src/monitor/collector.py` |
| **当前问题** | 指标通过字典手动收集，无类型安全 |
| **建议方案** | 迁移至 OpenTelemetry 标准 SDK |
| **预计人天** | 1 天 |
